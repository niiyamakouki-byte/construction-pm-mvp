# AI秘書（AssistantChatPanel）検証

対象は `AssistantChatPanel`（ラポルタ秘書）。GoodNotes や iPad の PDF 作業は含まない。

ローカルの `/help` は API を待たず、その場でコマンド一覧を返す。下の時間は「送信してからその文が見えるまで」の壁時計で、モデルの思考時間ではない。

## 計画

| 面 | 幅 | 見ること | 自動 |
| --- | --- | --- | --- |
| デスクトップ | 1440×900 | ヘッダー「AIに相談」で開く。パネルが画面内。`/help` がすぐ返る | Playwright |
| モバイル | 390×844 | FAB が下ナビと重ならない。開いたシートが画面幅に収まる。入力が見える | Playwright |
| モバイル | 412×915 | 同じ | Playwright |
| Capacitor Android | 実機 WebView | キーボードが入力を隠さない。FAB がシステムジェスチャと重ならない | 手動 |
| 工程表 `/gantt` | どちらも | 工程追加 FAB と重ならないよう、このページでは秘書 FAB を出さない（既存仕様） | コード上の分岐。今回の計測対象外 |

認証は `__E2E_BYPASS_AUTH__`。初回ウィザードは `genbahub_onboarding_done` と `genbahub_tour_done` と `genbahub:last-project-id` で止めた。

## 計測（Playwright / Chromium）

| 面 | 最初の返答 | FAB と下ナビ | パネル |
| --- | --- | --- | --- |
| 1440×900 | 開くまで 583ms。`/help` まで 413ms | FAB は出さない。入口はヘッダーの「AIに相談」 | 画面内に収まった |
| 390×844 | `/help` まで 15ms | FAB 下端 728px、ナビ上端 792px。重ならない | 開くアニメの途中を測ると幅 379px。画面外には出ていない |
| 412×915 | `/help` まで 374ms | FAB 下端 800px、ナビ上端 864px。重ならない | 幅 400px。画面内 |

15ms と 413ms の差は、ローカル処理そのものより、ボタンがアニメ後に安定するまでの待ちが混ざっている。どちらも 1.5 秒未満。

スクリーンショット: `desktop-1440-assistant.png`、`android-390-assistant.png`、`android-412-assistant.png`。

## 直したこと

1. 別の幅で保存したパネルサイズ（例: 幅 900px）が、390px の画面からはみ出していた。狭い幅では上から下までのシートにし、保存サイズを使わない。
2. キーボードで `visualViewport` が縮んでも、パネルの高さが 500px のままだと入力が隠れる。シートの高さは見えている高さに合わせる。単体テストで、高さ 340px・上端 80px のビューポートに追従することを確認した。
3. 日本語変換中の Enter で送信していた。変換中（`isComposing` または keyCode 229）は送らない。390px 未満の Enter は改行のままにし、送信はボタンだけにする。

## デスクトップの摩擦

サイドバーには秘書の項目がない。1440px ではヘッダーの「AIに相談」が常に見え、Ctrl+K でも開く。クリック 1 回でパネルが開いた。サイドバーを増やす変更はしていない。

## 実機でまだ見ること

- Android のキーボードを出したとき、入力欄がキーボードのすぐ上に残るか（自動テストは `visualViewport` の数値だけ）。
- 画面下のホームジェスチャと FAB の間隔。
- Capacitor WebView でフォーカス時にページ全体がずれないか。
- `/help` 以外の、Discord 経由の返答。開発サーバーではポーリングを止めてある。
